# i18n — Paparats desktop client

How UI copy, plurals and formatting work. `docs/architecture.md` §8 is the summary; this file is the
reference. `apps/desktop/src/i18n/i18n.test.ts` enforces most of it.

## 1. Modules

| Import | Exports |
|---|---|
| `@/i18n` | `i18n` (the i18next instance), `initI18n(locale)`, `changeLocale(locale)`, `LANGUAGES`, `LOCALES`, `isLocale(s)`, `toLocale(s)` |
| `@/i18n/format` | `useFormat(): Format`, `createFormat(locale, today): Format`, `type Format` |
| `@/i18n/createFormat` | the same `createFormat` and `Format`, free of React (for `domain/`, stores, tests) |
| `@/i18n/languages` | `LANGUAGES: readonly { code: Locale; native: string }[]` (English, Беларуская, Русский), `isLocale`, `toLocale` |

- `i18n` is ready in English the moment `@/i18n` is imported: resources are bundled and init is
  synchronous (`initAsync: false`, no Suspense), so tests need no async setup.
- `initI18n(locale)` sets the saved language at startup; `changeLocale(locale)` switches it. Both
  finish synchronously (the promise is a formality) and mirror the language on `<html lang>`.
- In components: `const { t } = useTranslation(); t("home.recentlyUpdated")`. Keys and
  interpolation variables are typed from the English catalog: an unknown key, a misspelled or
  missing variable, or a non-number `count` is a compile error (calling without any options is
  not caught). Build data-driven keys from typed ids (`` t(`categories.items.${id}.label`) `` with
  `id: CategoryId`; plan features with an index typed `1 | 2 | 3 | 4 | 5`).
- Because the English catalog is `as const`, `t()` is typed as the English literal
  (`t("nav.home")`: `"Home"`). Annotate when a variable takes several strings:
  `let label: string = t("common.get")`.
- `createFormat` is pure; the hook lives in `@/i18n/format` so non-React code can import
  `@/i18n/createFormat` without pulling in React or services.

## 2. Catalogs

- One i18next namespace (`translation`) per language. Inside it, one group per screen/area, one
  file each: `locales/<lang>/<area>.ts` (`about app browse categories channel common firstLaunch
  home idea ideas library nav profile report search settings shell sources subscription updates`),
  aggregated by `locales/<lang>/index.ts`.
- `en` is the source of truth and is declared `as const` (that is what types keys and variables).
  `be` and `ru` are typed `LocaleCatalog<typeof En>`: same keys, free plural forms.
- Adding a key: add it to all three languages in the same change. Keep the prototype's copy and
  tone; `common` holds strings used by more than one screen.
- `keymap.json` maps each prototype key (`t.xxx` in `Paparats Prototype.dc.html`) to its key here.
  Plural keys map to their base key (`appsCount` → `common.appsCount`).
- Catalog/editorial content (apps, channels, collections, hero slides, ideas, reviews, profile
  data) is not UI copy: it lives in `fixtures/` as `Localized<…>` values.

## 3. Plurals

- A plural string is a set of suffixed keys; call it by its **base key** with `count`:
  `t("common.appsCount", { count: apps.length })`. Never pick a suffix yourself.
- The variable is always `count`, and only plural strings use it (i18next switches to plural
  lookup whenever `count` is passed).
- Categories are the CLDR ones reported by `Intl.PluralRules(lang).resolvedOptions()`:
  en `_one _other`; be and ru `_one _few _many _other`. be/ru forms come from the prototype's
  `pl(n, one, few, many)`; `_other` covers fractions only (never an integer count) and repeats
  the `_few` form.
- A key is plural in every language or in none. When be/ru need a plural where the English
  prototype had none (e.g. `ratingsCount`), en gets `_one`/`_other` too, written naturally
  ("1 rating" / "3 ratings").
- Every form shows the count as `{{count, number}}`.

## 4. Variables and formatting

- **Numbers** are passed as numbers and rendered by i18next's built-in Intl formatter:
  `{{name, number}}` → `Intl.NumberFormat(<current language>)` (`12,400` / `12 400`). This applies
  to `count` and to every other numeric variable (`index`, `current`, `total`, `hours`).
- **Everything else is passed pre-formatted as a string** from `useFormat()`: dates
  (`{{date}}` ← `format.date` / `format.month`), relative times (`{{when}}` ← `format.relative`),
  sizes (`{{size}}`, `{{downloaded}}` ← `format.size`), prices (`{{price}}` ← `format.price`),
  lists (`{{channels}}` ← `format.list`); names are passed as they are.
- Never concatenate translated fragments into a sentence; add a key with variables instead.
  Joining independent labels with a separator (`version · size`) is fine.
- `escapeValue` is off: React escapes on render. Do not feed `t()` output to `innerHTML`.

Variable names (use these; the typed `t()` rejects others):

| Variable | Holds |
|---|---|
| `count` | plural count (number) |
| `app` | app display name |
| `channel` | channel display name (also the developer shown on ideas: "Nilesoft is on it") |
| `channels` | several channel names, joined with `format.list` |
| `author` | person name (channel author, idea author) |
| `category` | category label (`categories.items.<id>.label`) |
| `name` | an app **or** channel name (report dialog title) |
| `title` | idea title |
| `plan` | long plan name (`subscription.planNames.<id>`) |
| `email` | account email |
| `query` | search text as typed (trimmed) |
| `version` | version string (`1.8.9`) |
| `date` | `format.date(iso)` or `format.month(iso)` |
| `when` | `format.relative(iso)` ("yesterday", "3 days ago") |
| `price` | `format.price(amount, currency)` |
| `size`, `downloaded` | `format.size(mb)` |
| `current`, `total` | progress position and total (numbers) |
| `index` | 1-based position (number) |
| `hours` | number of hours (number) |

## 5. `useFormat()`

`useFormat()` = `createFormat(<current language>, useToday())`, memoised, re-rendering on a
language change. `createFormat` is pure (tests and non-React code use it directly). English uses
`en-GB` conventions for dates and numbers and `en-US` for prices; be and ru use their own tags.
Separators may be non-breaking spaces (as Intl emits them).

| Function | en | ru / be |
|---|---|---|
| `size(mb)` — at most one decimal | `18.4 MB`, `105 MB` | `18,4 МБ`, `105 МБ` |
| `sizeGb(mb)` — mb ÷ 1024, one decimal | `1.2 GB` | `1,2 ГБ` |
| `date(iso)` — local noon of `YYYY-MM-DD`; bad input is returned as is | `15 September 2026` | `15 сентября 2026 г.` / `15 верасня 2026 г.` |
| `month(iso)` | `September 2024` | `сентябрь 2024 г.` / `верасень 2024` |
| `relative(iso)` — vs today: under 1 day today, under 7 days, under 30 weeks (÷ 7, rounded), else months (÷ 30, rounded); `numeric: "auto"`; future dates → today | `today`, `yesterday`, `3 days ago`, `last week`, `2 months ago` | `5 дней назад` / `5 дзён таму` |
| `number(n)` | `1,234.5` | `1 234,5` / `1234,5` |
| `plus(n)` | `10,000+` | `10 000+` |
| `price(amount, currency)` — decimals only when there are cents | `$4.99`, `$0`, `$49` | `4,99 $`, `0 $`, `49 $` |
| `percent(n)` — n in 0–100, rounded | `46%` | `18 %` |
| `list(items)` — conjunction | `Nilesoft and Winaero` | `Nilesoft и Winaero` / `Nilesoft і Winaero` |

## 6. What the tests enforce (`i18n.test.ts`)

- be and ru have exactly the keys of en (plural suffixes aside); no key is plural in one language
  and not in another; every plural key has exactly the categories `Intl.PluralRules` reports.
- No `TODO`, empty or untrimmed strings, stray braces or `${…}` leftovers.
- The same `{{variables}}` (and formats) for a key in every language; `count` only in plural keys,
  always as `{{count, number}}`.
- Every `keymap.json` target exists (as a key or a plural base key).
- Every key that takes variables is listed in the table below.
- Plural selection for ru/be with 1, 2, 5, 11, 21, 22, 25; number grouping; `createFormat`.
