# Architecture — Paparats desktop client

The contract every contributor (human or agent) builds against. `CLAUDE.md` has the rules;
`design_handoff_paparats_store/` has the design; this file says **where things live and what
they are called**. When you add a module that others will use, add it here.

## 1. Map

```
apps/desktop/src/
  main.tsx                 entry: fonts, global CSS, <App/>
  bindings.ts              GENERATED by `pnpm specta` (Rust → TS types + commands). Never edit.
  app/                     shell: App, providers, router, layout, Sidebar, TopBar, WindowControls,
                           PageBanner, OfflineBanner, ToastHost, DialogHost, navigation helpers
  screens/<name>/          one folder per screen, public API = index.ts (`<Name>Screen`)
                           home browse categories updates library ideas idea subscription settings
                           profile app channel search dev first-launch
  components/<Name>/       shared components: <Name>.tsx + <Name>.module.css (+ test), index.ts
  services/                contracts.ts (interfaces), types.ts (domain types), errors.ts,
                           registry.ts (createServices + ServicesProvider + useServices),
                           mock/ (in-memory, fixtures), tauri/ (adapters over bindings.ts)
  queries/                 TanStack Query hooks over services (reads + mutations)
  stores/                  Zustand stores (UI + client state), one file per domain
  hooks/                   derived hooks combining queries + stores (useVisibleApps, useAppAction…)
  domain/                  pure functions: source rule, install state, filters, sorting, ideas,
                           app-page generators, settings schema. No React, fully unit-tested.
  i18n/                    i18next setup, locales/<lang>/<ns>.ts catalogs, format.ts (Intl)
  platform/                runtime detection, native window, storage wrappers
  styles/                  tokens.css (the only token layer), global.css, fonts.css
  assets/images/           WebP images converted from design_handoff/assets (same base names)
apps/desktop/src-tauri/    Tauri app: commands.rs, events, plugins, tray, window
crates/paparats-*/         Rust core (see STACK.md); paparats-core = domain model (source of truth)
fixtures/*.json            mock data set (ported from paparats-proto-data.js by scripts/port-fixtures.mjs)
```

## 2. Data flow

```
screen ─┬─ queries/* (TanStack Query) ─── services (contracts.ts) ─┬─ mock/*  (fixtures, timers)
        ├─ stores/*  (Zustand)                                      └─ tauri/* (bindings → Rust)
        ├─ hooks/*   (derived: queries + stores + domain/*)
        └─ components/*
```

- Screens and components never import `@/bindings` or `@tauri-apps/api/core` (ESLint enforces it).
- Domain types come from `@/services/types` (re-exports of the generated bindings).
- `createServices(mode)` picks `mock` or `tauri` once at startup (`platform/runtime.ts` ›
  `useMockServices()`: plain browser, Vitest or `PAPARATS_MOCK=1` → mock). Until a service's Rust
  commands exist, its tauri adapter delegates to the mock (flagged in `docs/decisions.md`).
- Mutations return the new authoritative state → `queryClient.setQueryData`, no refetch.

## 3. Services (see `services/contracts.ts`)

`catalog`, `install` (library: inventory + favorites + collections), `downloads`, `channels`,
`ideas`, `account`, `settings`, `system`. Access with `useServices()` only inside `queries/`,
`stores/` bridges and `hooks/`. Mock timings = the prototype's:

| What | Timing |
|---|---|
| Download tick | every 110 ms, +3–10 % per tick (`3 + random·7`), paused/offline ticks do nothing |
| Installing hold | 8 ticks (≈ 880 ms) at 100 % before `installed` |
| Concurrency | `settings.parallel` (default 2); the rest wait in `queued` |
| Check for app updates | 1 200 ms → `upToDate` |
| Other calls | resolve after ~40 ms (configurable; 0 in tests) |

Mock "today" is `fixtures/meta.json › today` (2026-09-15); the developer view acts as channel
`meta.developerChannel` (nilesoft); the idea thank-you runs until `meta.ideaBonusUntil`.

## 4. Queries (`queries/`)

Keys are `[service, method]`: `["catalog","getCatalog"]`, `["catalog","getPlatform"]`,
`["install","getLibrary"]`, `["channels","getChannels"]`, `["channels","getSubscriptions"]`,
`["ideas","getIdeas"]`, `["account","getAccount"]`. Exported as `queryKeys.*`.

Read hooks: `useCatalog()`, `usePlatform()`, `useLibrary()`, `useChannels()`,
`useSubscriptions()`, `useIdeas()`, `useAccount()` — each returns the TanStack `UseQueryResult`.

Mutation hooks (each returns an object of async functions that write the result into the cache):
`useLibraryActions()` {setFavorite, uninstall, open, openInstallFolder} ·
`useChannelActions()` {subscribe, unsubscribe, setPaused, acknowledgeStale, sync, report, lookup} ·
`useIdeaActions()` {vote, propose, comment, take, release, dismissReleaseNote} ·
`useAccountActions()` {updateProfile, removeDevice, setTwoFactor, purchase, cancelPlan,
claimIdeaBonus, signIn, signOut}.

## 5. Stores (`stores/`, Zustand)

| Store | State | Notes |
|---|---|---|
| `useUiStore` | `query`, `searching`, `toast {id,message}`, `navCount`, `loading` | `setQuery` (searching for 340 ms), `clearQuery`, `notify(msg)` (2.8 s), `beginNavigation()` (navCount+1, skeleton 420 ms unless animations are off) |
| `useSettingsStore` | `settings: Settings`, `hydrated` | `hydrate()`, `update(patch)` — optimistic, persists via SettingsService; applies theme/locale/motion to `<html>` |
| `useDownloadsStore` | `items: Record<AppId, DownloadItem>`, `order`, `batch {ids} \| null`, `justUpdated: Record<AppId,true>` | actions call DownloadService; kept in sync by `useDownloadsBridge()` (mounted once in providers) |
| `useBrowseStore` | `categories`, `pro`, `portable`, `sort` ('featured'\|'newest'\|'name'\|'size'), `collection`, `filterQuery`, `sources`, `heroIndex` | `apply(preset)` replaces filters (used by navigation into Browse), `clearAll()` |
| `useLibraryStore` | `tab`, `sort` ('recent'\|'name'\|'size'), `view` ('list'\|'grid'), `collection`, `filter` ('all'\|'updates'\|'downloads'\|'favorites'), `menuFor` | |
| `useUpdatesStore` | `expanded: Record<AppId,boolean>` (vscode, obsidian open), `historyOpen` | |
| `useIdeasStore` | `tab`, `statuses`, `sort` ('top'\|'new'), `appFilter` | |
| `useHomeStore` | `heroIndex` | |
| `useDialogStore` | `dialog: DialogState \| null` | `open(d)`, `close()`; rendered by `app/DialogHost` |

`DialogState` = `{kind:'plan', plan:'monthly'|'yearly'}` · `{kind:'addChannel'}` ·
`{kind:'trustConfirm', channelId}` · `{kind:'report', target: ReportTarget}` ·
`{kind:'suggestIdea', appId?}` · `{kind:'releaseIdea', ideaId}`.

## 6. Derived hooks (`hooks/`) and domain functions (`domain/`)

Hooks (names are the contract):
- `useToday(): IsoDate` — from SystemService.
- `useOffline(): boolean` — real connectivity OR `settings.simulateOffline`.
- `useViewAs(): 'user' | 'developer'` — developer when `settings.dev && settings.viewAsDeveloper`.
- `useChannelContext()` — `{ channels, byId, subscriptions, isActive(id), sourceOf(app), alternativesOf(app), downDays(id), isStale(id) }` (source rule: most trusted *active* channel; official › verified › community).
- `useVisibleApps(): App[]` — apps whose channels are followed and enabled, plus installed ones.
- `useAppIndex()` — `{ byId, get(id) }` over the full catalog.
- `useInstallState(appId): AppInstallState` — `'none'|'installed'|'update'|'queued'|'downloading'|'paused'|'installing'` + `progress`, `installedVersion`.
- `useAppAction(app)` — the primary card/button action exactly like the prototype's `card()`:
  label (Get / Open / Update / Subscribe / Offline / Queued / Installing… / `NN% · Pause` /
  Resume), `tone` ('neutral'|'primary'|'progress'|'muted'), `disabled`, `run()`, `cancel()`.
- `useUpdates()` — `{ apps, count, totalMb }` pending updates (installed ≠ catalog version,
  source channel active and reachable).
- `usePro()` — `{ isPro, isGift, planId, renewsOn, giftUntil }`.
- `useFormat()` (from `i18n/format.ts`) — `size(mb)` "18.4 MB"/"18,4 МБ", `sizeGb(mb)`,
  `date(iso)` "15 September 2026", `month(iso)`, `relative(iso)` (days/weeks/months vs today),
  `number(n)`, `plus(n)` "10,000+", `price(amount, currency)`, `percent(n)`.

Domain modules: `domain/channels.ts`, `domain/apps.ts` (install state, filters, sorting, search
matching over name/publisher/tagline/category/source channel), `domain/ideas.ts` (tab filters,
`canTake`, `nextVersion`, `excerpt`), `domain/appDetail.ts` (deterministic rating, histogram,
reviews, version history — the prototype's generators), `domain/settings.ts` (`DEFAULT_SETTINGS`,
`SETTINGS_SECTIONS`, `SETTINGS_ROWS` schema), `domain/text.ts` (`pickText`, `initials`),
`domain/dates.ts`.

## 7. Navigation (`app/navigation.ts`)

Memory router (react-router 8, `createMemoryRouter`). Routes: `/home` `/browse` `/categories`
`/updates` `/library` `/ideas` `/ideas/:ideaId` `/subscription` `/settings/:section?` `/profile`
`/app/:appId` `/channel/:channelId` `/dev`; `/` → `/home`.

`useNav()` returns `go(target)` and `back()`. `target` is a typed union, e.g.
`{to:'app', appId}`, `{to:'browse', filters?: Partial<BrowseFilters>}`, `{to:'settings', section?}`,
`{to:'ideas', appFilter?}`, `{to:'idea', ideaId}`, `{to:'channel', channelId}`.
Detail screens (app, channel, idea) remember the section they were opened from; the sidebar keeps
that section active and `back()` returns to it. Every navigation clears the search query, bumps
`navCount` (skeleton 420 ms + 340 ms enter animation) and scrolls the content to the top.

Search is not a route: while `useUiStore.query` is non-empty the content area renders
`<SearchScreen/>` instead of the route outlet.

## 8. i18n

- One i18next namespace (`translation`) per language, grouped by screen: `locales/<lang>/<ns>.ts`
  (`common nav shell search home browse categories app updates library subscription settings about
  sources channel report profile ideas idea firstLaunch`, plus areas added later). Use
  `const { t } = useTranslation(); t("home.recentlyUpdated")` — keys are typed.
- `i18n/keymap.json` maps every prototype key (`t.xxx` in the prototype) to its new key.
- Plurals: i18next suffixes (`_one`, `_few`, `_many`, `_other`) resolved with `Intl.PluralRules`;
  the variable is always `count`. Interpolation variables are named in `docs/i18n.md`.
- Never concatenate sentences; format numbers/dates/sizes only through `useFormat()`.
- en / be / ru must stay in sync — `i18n.test.ts` fails on a missing key or plural form.

## 9. Styling

- CSS Modules + `styles/tokens.css`. Only `var(--*)` for colours, radii, shadows, spacing, type
  sizes; the on-image and brand colours have tokens too. No literal hex/rgba in components
  (exception: per-item data colours such as app/channel tints passed through `style`).
- Themes: `data-theme="dark"|"light"` on `<html>`; "System" follows `matchMedia` /
  Tauri `onThemeChanged`. Motion: `data-motion="off"` when "Subtle animations" is off.
- Focus: `:focus-visible { outline: 2px solid var(--mint); outline-offset: 2px }`. Hit targets ≥ 32 px.
- Icons: `lucide-react` through `components/Icon` (`<Icon name="layout-grid" size={20} />`,
  stroke 1.75, round caps/joins), so data can name icons (fixtures use lucide kebab-case names).
- App icons: `components/AppIcon` — `iconUrl` when present, else the monogram tile (`mono` on `tint`).

## 11. Testing

- Vitest + Testing Library (jsdom). Render with `renderWithProviders()` from `src/test/render.tsx`
  (mock services with 0 ms latency, fresh QueryClient, i18n in `en`, memory router).
- Pure `domain/*` functions get unit tests; stores get behaviour tests; each screen gets at least
  one smoke test plus tests for its end-to-end flows.
- Rust: unit tests per crate; `crates/paparats-core/tests/fixtures.rs` keeps fixtures ↔ model in sync.
