# Architecture — Paparats desktop client

The contract every contributor (human or agent) builds against. `CLAUDE.md` has the rules;
`design_handoff_paparats_store/` has the design; this file says **where things live and what
they are called**. When you add a module that others will use, add it here.

## 1. Map

```
apps/desktop/src/
  main.tsx                 entry: fonts/tokens/global CSS, createServices → bootstrap() → <App/>
  bindings.ts              GENERATED by `pnpm specta` (Rust → TS types + commands). Never edit.
  app/                     shell: App, bootstrap, providers, routes, navigation (useNav), Layout,
                           Sidebar, TopBar, WindowControls, OfflineBanner, NavigationSkeleton,
                           ToastHost, DialogHost, documentSettings (theme/motion/locale → <html>);
                           app/dialogs/ holds the dialogs DialogHost renders (PlanDialog, ReportDialog)
  screens/<name>/          one folder per screen, public API = index.ts (`<Name>Screen`)
                           home browse categories updates library ideas idea subscription settings
                           profile app channel search dev first-launch
  screens/shared/          connected pieces several screens share (StoreAppCard, useStoreAppView,
                           toActionView, useDownloadStatus, useProStatusView) — they read hooks
                           and navigate, unlike components/
  components/<Name>/       shared components: <Name>.tsx + <Name>.module.css (+ test), index.ts
  services/                contracts.ts (interfaces), types.ts (domain types), errors.ts,
                           registry.ts (createServices + ServicesProvider + useServices),
                           mock/ (in-memory, fixtures), tauri/ (adapters over bindings.ts)
  queries/                 TanStack Query hooks over services (reads + mutations)
  stores/                  Zustand stores (UI + client state), one file per domain
  hooks/                   derived hooks combining queries + stores (useVisibleApps, useAppAction…)
  domain/                  pure functions: source rule, install state, filters, sorting, ideas,
                           app-page generators, settings schema. No React, fully unit-tested.
  i18n/                    i18next setup, locales/<lang>/<ns>.ts catalogs, format.ts (Intl)
  platform/                runtime detection (`isTauri`, `shouldUseMockServices`), native window
  styles/                  tokens.css (the only token layer), global.css, fonts.css
  test/                    setup.ts (jest-dom), render.tsx (renderWithProviders, renderApp)
  assets/images/           WebP images converted from design_handoff/assets (same base names)
apps/desktop/src-tauri/    Tauri app: commands.rs, events, plugins, tray, window
crates/paparats-*/         Rust core (see STACK.md); paparats-core = domain model (source of truth)
fixtures/*.json            mock data set (ported from paparats-proto-data.js by scripts/port-fixtures.mjs)
```

## 2. Data flow

```
screen ─┬─ queries/* (TanStack Query) ─── services (contracts.ts) ─┬─ mock/*  (fixtures, timers)
        ├─ stores/*  (Zustand)                                      └─ tauri/* (bindings → Rust)
        ├─ hooks/*   (derived: queries + stores + domain/*)
        └─ components/*
```

- Screens and components never import `@/bindings` or `@tauri-apps/api/core` (ESLint enforces it).
- Domain types come from `@/services/types` (re-exports of the generated bindings).
- `createServices(mode)` picks `mock` or `tauri` once at startup (`platform/runtime.ts` ›
  `shouldUseMockServices()`: plain browser, Vitest or `PAPARATS_MOCK=1` → mock). The tauri set
  calls the Rust commands for every service; settings live in `settings.json` through
  tauri-plugin-store (`docs/decisions.md` D26).
- Startup (`main.tsx`): `createServices()` → `app/bootstrap.ts › bootstrap(services)` (installs the
  set, hydrates `useSettingsStore`, applies theme/motion to `<html>`, `initI18n(locale)`) → render
  `<App services/>`. The first frame already has the user's theme and language.
- Mutations return the new authoritative state → `queryClient.setQueryData`, no refetch.

## 3. Services (see `services/contracts.ts`)

`catalog`, `install` (library: inventory + favorites + collections), `downloads`, `channels`,
`ideas`, `account`, `settings`, `system`. Access with `useServices()` only inside `queries/`,
`stores/` bridges and `hooks/`. Mock timings = the prototype's:

| What | Timing |
|---|---|
| Download tick | every 110 ms, +3–10 % per tick (`3 + random·7`), paused/offline ticks do nothing |
| Installing hold | 8 ticks (≈ 880 ms) at 100 % before `installed` |
| Concurrency | `settings.parallel` (default 2); the rest wait in `queued` |
| Check for app updates | 1 200 ms → `upToDate` |
| Other calls | resolve after ~40 ms (configurable; 0 in tests) |

Mock "today" is `fixtures/meta.json › today` (2026-09-15); the developer view acts as channel
`meta.developerChannel` (nilesoft); the idea thank-you runs until `meta.ideaBonusUntil`.

## 4. Queries (`queries/`)

Keys are `[service, method]`: `["catalog","getCatalog"]`, `["catalog","getPlatform"]`,
`["install","getLibrary"]`, `["channels","getChannels"]`, `["channels","getSubscriptions"]`,
`["ideas","getIdeas"]`, `["account","getAccount"]`. Exported as `queryKeys.*`.

Read hooks: `useCatalog()`, `usePlatform()`, `useLibrary()`, `useChannels()`,
`useSubscriptions()`, `useIdeas()`, `useAccount()` — each returns the TanStack `UseQueryResult`.

Mutation hooks (each returns an object of async functions that write the result into the cache):
`useLibraryActions()` {setFavorite, uninstall, open, openInstallFolder} ·
`useChannelActions()` {subscribe, unsubscribe, setPaused, acknowledgeStale, sync, report, lookup} ·
`useIdeaActions()` {vote, propose, comment, take, release, dismissReleaseNote} ·
`useAccountActions()` {updateProfile, removeDevice, setTwoFactor, purchase, cancelPlan,
claimIdeaBonus, signIn, signOut}.

One-off service calls with nothing to cache (`queries/system.ts`): `useSystemActions()`
{checkForAppUpdate, openExternal, copyToClipboard, setAutostart} · `useSettingsActions()`
{clearSearchHistory} (the settings themselves go through `useSettingsStore`).

## 5. Stores (`stores/`, Zustand)

| Store | State | Notes |
|---|---|---|
| `useUiStore` | `query`, `searching`, `toast {id,message}`, `navCount`, `loading` | `setQuery(q, {skeleton?})` (searching for 340 ms), `clearQuery`, `notify(msg)` (2.8 s), `dismissToast`, `beginNavigation({skeleton})` (clears the search, navCount+1, skeleton 420 ms when `skeleton`) |
| `useSettingsStore` | `settings: Settings`, `hydrated` | `hydrate()`, `update(patch)` — optimistic, persists via SettingsService, rolls back on failure. Never touches the DOM: `app/documentSettings.ts` applies theme/locale/motion to `<html>` |
| `useDownloadsStore` | `items: Record<AppId, DownloadItem>`, `order`, `batch {ids} \| null`, `justUpdated: Record<AppId,true>` | actions call DownloadService (`enqueue`, `startBatch`, pause/resume/cancel (+All), `clearJustUpdated(id?)`); selectors `batchProgress`, `allPaused`; kept in sync by `useDownloadsBridge()` (`stores/useDownloadsBridge.ts`, mounted once in the providers) |
| `useBrowseStore` | `categories`, `pro`, `portable`, `sort` ('featured'\|'newest'\|'name'\|'size'), `collection`, `filterQuery`, `sources`, `heroIndex` | `apply(preset)` resets the six filters then applies the preset (navigation into Browse), `clearAll()`, toggles, `dropSource(id)` (unsubscribe/pause); select filters with `useShallow(selectBrowseFilters)` |
| `useLibraryStore` | `tab`, `sort` ('recent'\|'name'\|'size'), `view` ('list'\|'grid'), `collection`, `filter` ('all'\|'updates'\|'downloads'\|'favorites'), `menuFor` | `setTab` (also on the current tab: closes the collection, resets the quick filter), `setFilter` (switches to Installed), `openCollection`, `closeCollection`, `toggleMenu`/`closeMenu`. Kept across navigation like the prototype's state; `go()` only closes the menu |
| `useUpdatesStore` | `expanded: Record<AppId,boolean>` (vscode, obsidian open), `historyOpen` | `toggleExpanded(id)`, `toggleHistory()` |

| `useHomeStore` | `heroIndex`, `heroGlow` | `setHeroIndex`, `step(delta, count)`, `setHeroGlow(on)` (the first-launch exit turns the hero glow on, then off after ~1.7 s — M6) |

| `useProfileStore` | `tab` ('account'\|'preferences'\|'security'\|'devices'\|'data'), `editing`, `draft {name,email} \| null`, `byKeyboard` | `setTab`, `startEdit(profile)`, `setDraft`, `endEdit()`, `noteActivation(byKeyboard)` (keyboard focus follows the header's mode switch). `DialogState` = `{kind:'plan', plan:'monthly'|'yearly'}` · `{kind:'addChannel'}` ·
`{kind:'trustConfirm', channelId}` · `{kind:'report', target: ReportTarget}` ·
`{kind:'suggestIdea', appId?}` · `{kind:'releaseIdea', ideaId}`.

## 6. Derived hooks (`hooks/`) and domain functions (`domain/`)

Hooks (names are the contract):
- `useToday(): IsoDate` — from SystemService.
- `useOffline(): boolean` — real connectivity OR `settings.simulateOffline`.
- `useViewAs(): 'user' | 'developer'` — developer when `settings.dev && settings.viewAsDeveloper`.
- `useChannelContext()` — `{ channels, byId, subscriptions, ready, subscriptionOf(id), isFollowed(id), isActive(id), sourceOf(app), alternativesOf(app), downDays(id), isStale(id) }` (source rule: most trusted *active* channel; official › verified › community).
- `useVisibleApps(): App[]` — apps whose channels are followed and enabled, plus installed ones.
- `useAppIndex()` — `{ byId, get(id) }` over the full catalog.
- `useInstalledIndex(): InstalledIndex` — `Map<AppId, InstalledApp>` over the library.
- `useInstallState(appId)` — `{ state: AppInstallState, progress, installedVersion }`;
  `AppInstallState` = `'none'|'installed'|'update'|'queued'|'downloading'|'paused'|'installing'`.
- `useAppAction(app)` — the primary card/button action exactly like the prototype's `card()`:
  label (Get / Open / Update / Subscribe / Offline / Queued / Installing… / `NN% · Pause` /
  Resume), `tone` ('neutral'|'primary'|'progress'|'quiet' (queued)|'muted' (offline)),
  `disabled`, `run()`, `cancel()`.
- `useLocale(): Locale` — the UI language as a catalog locale, for `pickText` / `pickLocalized`
  (the prototype's `L()`) and locale-aware sorting.
- `useUpdates()` — `{ apps, count, totalMb }` pending updates (installed ≠ catalog version,
  source channel active and reachable).
- `usePro()` — `{ isPro, isGift, planId, renewsOn, giftUntil }`.
- `useFormat()` (from `i18n/format.ts`) — `size(mb)` "18.4 MB"/"18,4 МБ", `sizeGb(mb)`,
  `date(iso)` "15 September 2026", `month(iso)`, `relative(iso)` (days/weeks/months vs today),
  `number(n)`, `plus(n)` "10,000+", `price(amount, currency)`, `percent(n)`,
  `list(items)` "Nilesoft and Winaero". The same functions without React:
  `@/i18n/createFormat › createFormat(locale, today)` (domain code, stores, tests).
- Test-only helpers for hooks: `hooks/testing.tsx` (`createTestServices`, `renderWithServices`,
  `flush`, `resetStores`); not exported by the barrel.

Domain modules: `domain/channels.ts`, `domain/apps.ts` (install state, filters, sorting, search
matching over name/publisher/tagline/category/source channel, `pickByIds` — the prototype's
`byIds()` for featured/notable/collection lists, hidden ids skipped), `domain/ideas.ts` (tab filters,
`canTake`, `nextVersion`, `excerpt`, `releaseNotes` for the sidebar Ideas badge),
`domain/appDetail.ts` (deterministic rating, histogram,
reviews, version history — the prototype's generators), `domain/settings.ts` (`DEFAULT_SETTINGS`,
`SETTINGS_SECTIONS`, `SETTINGS_ROWS` schema), `domain/text.ts` (`pickText`, `initials`),
`domain/dates.ts`.

## 7. Navigation (`app/navigation.ts`)

Memory router (react-router 8, `createMemoryRouter`). Routes: `/home` `/browse` `/categories`
`/updates` `/library` `/ideas` `/ideas/:ideaId` `/subscription` `/settings/:section?` `/profile`
`/app/:appId` `/channel/:channelId` `/dev`; `/` → `/home`.

`useNav()` returns `{ section, go(target), back() }`. `target: NavTarget` is a typed union:
`{to:'home'|'categories'|'updates'|'library'|'subscription'|'profile'|'dev'}` ·
`{to:'browse', filters?: Partial<BrowseFilters>}` · `{to:'ideas', appFilter?: AppId | null}` ·
`{to:'settings', section?: SettingsSectionId}` · `{to:'app', appId}` · `{to:'channel', channelId}` ·
`{to:'idea', ideaId}`. Pure helpers: `pathOf(target)`, `parsePath(path)`, `sectionOfPath(path)`,
`activeSection(path, state)`, `returnPath(path, state)`, `initialPathFromHash(hash)`.

- Detail screens (app, channel, idea) get router state `{ from: <return path> }`: the full path,
  so Settings › Sources is restored, and a detail opened from a detail keeps the original. The
  sidebar highlights `section` (the detail's origin) and `back()` goes to the return path (Home
  when the detail was opened directly).
- Every `go()` clears the search, closes the Library ⋯ menu, bumps `navCount` (the content scrolls
  to the top and replays the 340 ms enter animation) and shows the 420 ms skeleton unless
  "Subtle animations" is off. Leaving `/updates` clears the "Updated just now" markers.
- Browse: `filters` given → `apply(filters)` (every filter reset, then the preset; the sidebar
  passes `{}`); absent (e.g. `back()`) → filters kept, the source filter cleared (prototype).
  Ideas: `appFilter` given → `focusApp(appFilter)`.
- Inside Settings, picking a section is not a `go()`: the screen calls react-router's
  `navigate(pathOf({to:'settings', section}), {replace:true})`, so the panel swaps without the
  skeleton, enter animation or scroll reset (the prototype's `setState({section})`), while the path
  still carries the section for detail pages that return to it. `/settings` opens General.
- `/dev` (component gallery, a lazy chunk) is opened from Settings › Advanced › Component gallery
  in developer mode (schema row `gallery`, link `dev`; rendered by the Settings screen), or in a
  plain browser with `http://localhost:1420/#/dev` (the initial route comes from the URL hash;
  unknown paths start at Home).

Search is not a route: while `useUiStore.query` is non-blank the content area renders
`<SearchScreen/>`; the route outlet stays mounted (hidden) underneath so its state survives.

## 8. i18n

- One i18next namespace (`translation`) per language, grouped by screen: `locales/<lang>/<ns>.ts`
  (`common nav shell search home browse categories app updates library subscription settings about
  sources channel report profile ideas idea firstLaunch`, plus areas added later). Use
  `const { t } = useTranslation(); t("home.recentlyUpdated")` — keys are typed.
- `i18n/keymap.json` maps every prototype key (`t.xxx` in the prototype) to its new key.
- Plurals: i18next suffixes (`_one`, `_few`, `_many`, `_other`) resolved with `Intl.PluralRules`;
  the variable is always `count`. Interpolation variables are named in `docs/i18n.md`.
- Never concatenate sentences; format numbers/dates/sizes only through `useFormat()`.
- en / be / ru must stay in sync — `i18n.test.ts` fails on a missing key or plural form.
- The full reference (modules, key shapes, plural rules, every key that takes variables) is
  `docs/i18n.md`.

## 9. Styling

- CSS Modules + `styles/tokens.css`. Only `var(--*)` for colours, radii, shadows, spacing, type
  sizes; the on-image and brand colours have tokens too. No literal hex/rgba in components
  (exception: per-item data colours such as app/channel tints passed through `style`).
- Themes: `data-theme="dark"|"light"` on `<html>` (set by `app/documentSettings.ts`); "System"
  follows `prefers-color-scheme` (WebView2 mirrors the Windows setting). Theme blocks in
  `tokens.css` use bare `[data-theme]` selectors, so any subtree can switch theme (the `/dev`
  gallery renders both side by side). Motion: `data-motion="off"` when "Subtle animations" is off
  (the tokens' durations drop to 0; the navigation skeleton is skipped).
- The content column padding is `--content-pad` (8px 30px 40px, prototype line 134); `PageBanner`
  bleeds through it with `--content-pad-top` / `--content-pad-x`.
- Focus: `:focus-visible { outline: 2px solid var(--mint); outline-offset: 2px }`. Hit targets ≥ 32 px.
- Icons: `lucide-react` through `components/Icon` (`<Icon name="layout-grid" size={20} />`,
  stroke 1.75, round caps/joins), so data can name icons (fixtures use lucide kebab-case names).
- App icons: `components/AppIcon` — `iconUrl` when present, else the monogram tile (`mono` on `tint`).

source-channel chips, chevron-down "Details", identity and chevron open the app page — is

## 11. Testing

- Vitest + Testing Library (jsdom). `src/test/render.tsx`:
  `await renderWithProviders(ui, { route?, services? })` (app providers and a memory router whose
  every path renders `ui`) and `await renderApp({ route?, services? })` (the whole shell). Both use
  mock services with 0 ms latency and in-memory settings, hydrate settings first, and use a fresh
  QueryClient and i18n in `en`. Importing the module registers the cleanup (unmount, dispose the
  services, reset the stores, the `<html>` attributes and the language).
- Pure `domain/*` functions get unit tests; stores get behaviour tests; each screen gets at least
  one smoke test plus tests for its end-to-end flows.
- Each milestone's end-to-end flows also run through the whole shell (`renderApp`) in one file
  per milestone, which fails on any `console.error`/`console.warn`: `app/discovery.test.tsx` (M2),
  `app/libraryUpdates.test.tsx` (M3), `app/account.test.tsx` (M4).
- Rust: unit tests per crate; `crates/paparats-core/tests/fixtures.rs` keeps fixtures ↔ model in sync.
